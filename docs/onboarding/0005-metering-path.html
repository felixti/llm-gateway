The Metering Path — At-Least-Once, Billed-Once

How a usage event survives a queue outage, a crash, and duplicate delivery — and still gets counted exactly once. ~12 min.

Warm-up (cold recall from L04 — no peeking): name the three budget Lua scripts, and say what COMMIT moves from where to where.
check yourself

RESERVE · COMMIT · RELEASE. COMMIT moves the amount from :reserved → :spent (INCRBY spent, DECRBY reserved, DEL resv), idempotent via the commit key.

Win: you can trace a UsageEvent from the handler to an ADX row, name every durability hop (queue → WAL → replayer), and explain the one KQL trick that turns "at-least-once delivery" into "counted once, and the right once."

1 · The path, end to end

handler ── buildUsageEvent ──► emitUsageEvent │ enqueue OK ───┤─── enqueue THROWS ▼ ▼ Azure Storage Queue WAL (disk DLQ) unbilled-<reqId>.json ▲ │ 0600 file in 0700 dir │ replayer ─────┘ tmp-write + atomic rename │ (interval; enqueue then delete file) ▼ Collector worker ── receive(≤32, vis 30s) ──► batch file ──► delete msgs │ ▼ ADX Usage table ──► UsageDedup materialized view (arg_max by request_id)

2 · Durability is layered, idempotency is deferred

Every hop is at-least-once, on purpose. Nothing tries to be exactly-once in the pipe — that's pushed to the very end (ADX). The layers:

HopFailure it survivesHow
enqueue → WALqueue unreachableemitUsageEvent catches the throw, writes the event to disk instead
WAL durabilitycrash mid-writewrite .tmp then rename — POSIX-atomic, no half file ever read; 0600/0700 perms; reqId regex-guarded
replayerqueue was down, now backinterval drains WAL → enqueue → delete file; leaves file on failure for next tick
queue visibilitycollector crashes mid-batch30s visibility timeout → unacked message reappears, redelivered
ADX dedupthe duplicates all of the above createarg_max(...) by request_id collapses them to one row
The gem — read this twice. The dedup view doesn't just pick any copy of a request_id; it picks the right one: 
_rank = iff(redis_commit_result == 'ok' and tokens_total > 0, ts + 3650d, ts)
| summarize arg_max(_rank, *) by request_id
A copy that was actually billed (redis_commit_result=='ok' and has tokens) gets its timestamp pushed 10 years into the future, so arg_max always prefers the successfully-committed record over a failed/partial duplicate of the same request. At-least-once in, the correct single row out.

3 · The event carries its own billing truth

The UsageEvent isn't just tokens + cost. It carries redis_commit_result ('ok'|'failed'), reservation_id, scope, and attempt. So even if the budget COMMIT to Redis failed, the event is still emitted — the failure is a field, not a dropped record. ADX can then reconcile what was charged vs. what was used. Metering never silently loses a request.

6 · Strength & weakness (mission lens)

Strength

Metering is decoupled from the request path — an ADX outage never slows a user. Durability is layered and self-healing (WAL + replayer). Idempotency is solved once, at the read side, with a view that also encodes "prefer the billed record." The event self-describes its billing state, so nothing is silently lost.

Weakness / MVP cut

The "ADX sink" is stubbed: the collector writes local batch JSON files, not real ADX ingest yet (ADR-0012). WAL's default dir is /tmp/ai-gateway-wal — on a tmpfs/ephemeral host a reboot can lose unbilled entries; set WAL_DIR to durable storage. And remember L04: cost_usd here is the 1.2× estimate, so ADX analytics inherit that over-count until billing-on-actuals lands.

7 · Blank-page self-test

Trace one event from handler to a single ADX row, through one queue outage. Reveal.

emit: buildUsageEvent → enqueue throws (queue down) → WAL writes unbilled-<reqId>.json (tmp+rename, 0600). Queue recovers → replayer tick enqueues it, deletes the file. Collector receive(≤32, vis 30s) → writes batch file → deletes messages. If it crashed first, the message reappears after 30s (a duplicate). ADX: both copies land; UsageDedup ranks the committed+tokens copy via ts+3650d and arg_max by request_id keeps that one. Counted once, the right once.
