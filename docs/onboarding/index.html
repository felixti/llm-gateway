LLM Gateway — Onboarding

Nine short, interactive lessons that build a working mental model of this system — grounded in the live code, not the prose docs.

This is a guided path through the AI Gateway: the two-plane architecture, the request pipeline, the trust model, the budget engine, metering, resilience, the protocol bridge, and the MVP cut — finishing with an honest strengths-and-weaknesses synthesis. Each lesson is a single self-contained page with active-recall drills (the quizzes give instant feedback). Work them in order; each opens by re-testing the previous one.

Read this first — the most important thing for a new joiner. The repo's CLAUDE.md/AGENTS.md describe a system that is substantially the retired legacy app (Bun, PostgreSQL, PATs, circuit breaker, retry, streaming) — not the live MVP. The live system is services/{edge,gateway,collector} + packages/shared + contracts/; the rationale is in the ADRs. When the prose docs and the code disagree, the code wins. Lesson 06 covers this gap directly.

The lessons

  1. The Two-Plane Architecture Why a .NET/YARP edge sits in front of a Node/Hono brain — and the alternatives that were rejected.
  2. The Request Pipeline, Hop by Hop The seven gates a request passes inside the Node plane, in order, and what stops it at each.
  3. The Trust Model — No mTLS, No Problem? Why blindly trusting identity headers is safe here — and the one defense layer that isn't built.
  4. The Budget Engine — Atomic Money in Redis Microdollars, three Lua scripts, the hash-tag that makes it cluster-safe, and what's really charged.
  5. The Metering Path — At-Least-Once, Billed-Once Queue → Collector → ADX, the WAL disk DLQ, and the dedup view that counts each request once.
  6. Resilience — Vision vs. MVP The map-vs-territory lesson: the resilience the docs describe lives only in legacy/.
  7. The Protocol Bridge — Chat ⇄ Responses The one piece of real translation logic: four transforms that let a client protocol target any model.
  8. The MVP Cut — Vision Minus Everything Deferred How ADR-0010..0015 each reversed or narrowed the grand vision so the MVP could ship.
  9. Capstone — Strengths & Weaknesses Three defensible strengths, three weaknesses to name first, and mixed recall across the whole course.

Reference: the glossary — the project's ubiquitous language; the lessons adhere to it.

How to read these. Open them in a browser (they're static HTML — no build, no server needed; just open the file). Do the drills, don't just read them — the retrieval practice is the point. Pair each lesson with its cited primary source (an ADR or a code file) for the full picture.
