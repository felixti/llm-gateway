1 · Money is an integer (microdollars)

No floats. shared/budget/money.ts stores USD as microdollars — USD × 1,000,000 as a bigint. $0.000001 precision, exact integer arithmetic, no rounding drift. The 1.2× reserve multiplier is done in integer space too (multiplyMicro scales by 1000 and rounds up). Redis only ever stores and INCRBYs these integers.

"0.001500" ──toMicrodollars──► 1500n (bigint microdollars) reserve = multiplyMicro(1500n, 1.2) = 1800n ← the 1.2× hold, integer, rounded up fromMicrodollars(1800n) ──► "0.001800"

2 · The keys per scope

A scope is the budget owner: {user:<id>} or {proj:<id>}. Those braces are not decoration — read §4.

KeyTypeHolds
{scope}:policyhashcap_micro, hard, period — synced from Table Storage
{scope}:spentintcommitted actuals (the real charge)
{scope}:reservedintoutstanding pre-flight holds
{scope}:resv:<id>int + TTLone reservation's amount; auto-expires (orphan cleanup)
{scope}:commit:<reqId>int + TTLidempotency marker — a request commits once

3 · Three atomic scripts = the lifecycle

Each script is one Redis round-trip, executed atomically (no interleaving between calls):

ScriptWhenWhat it does
RESERVEhop 6, before upstream cap≤0 → insufficient. If spent+reserved+cost > cap and hard → insufficient. Else INCRBY reserved + SET resv EX ttl.
COMMIThandler, after upstream OK idempotent (commitKey exists → already). Else INCRBY spent, DECRBY reserved, DEL resv, set commitKey.
RELEASEabort / no-charge path DECRBY reserved + DEL resv. Idempotent (missing resv → ok).
RESERVE (1.2× hold) ──► upstream call ──► COMMIT (move hold: reserved→spent) │ ▲ └── on failure/abort ── RELEASE ─────┘ (or just let resv TTL expire)

4 · The one brace that makes it cluster-safe

Every script touches 3–4 keys at once. On a Redis Cluster (ADR-0013, Azure Managed Redis), a multi-key command only works if all keys live in the same hash slot. The scope tag {user:abc} wraps the id in { } — Redis's hash-tag syntax — so {user:abc}:spent, :reserved, :policy, :resv:… all hash to one slot. That's why the atomic Lua works in production, not just on a single node.

Gotcha you should know cold: in the MVP, COMMIT charges spent the reserved amount (the 1.2× estimate), not the actual token cost. In finalizeRequest, actualMicro = reservedMicro and the usage event's cost_usd = fromMicrodollars(reservedMicro). Real token counts are extracted for the event, but the charge is the padded estimate. Billing-on-actuals is deferred.

7 · Strength & weakness (mission lens)

Strength

Concurrency-correct by construction: each decision is one atomic Lua round-trip, so two requests can't both "fit" into the last dollar. Integer microdollars = no float drift. Commit is idempotent (safe to retry). Hash-tag makes it cluster-native. Orphaned holds self-heal via the resv TTL.

Weakness / debt

Charges the estimate, not actuals (1.2× over-bills every request until billing-on- actuals ships). The handler doesn't call RELEASE on upstream error — it leans on the resv TTL to free the hold (transient over-reservation). And COMMIT's not_found branch (reservation expired before commit) surfaces in the store as a thrown error → logged as redis_commit_result: failed.

8 · Blank-page self-test

Trace $0.0015 of estimated cost through reserve→commit. Name keys touched. Reveal.

1500n est → multiplyMicro(…,1.2)=1800n. RESERVE: read :policy cap; check :spent + :reserved + 1800 ≤ cap; INCRBY :reserved 1800; SET :resv:<id> 1800 EX ttl. Upstream returns. COMMIT: commitKey absent → INCRBY :spent 1800 (the hold, not actuals), DECRBY :reserved 1800, DEL :resv:<id>, SET :commit:<reqId>. All keys share slot via the { } tag.
